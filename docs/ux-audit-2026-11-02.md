# UX/UI audit — Oura Insights dashboard
Date: 2026-11-02. Scope: repository source inspection, NOT a browser screenshot or usability study.

## Method and confidence

Reviewed current dashboard/app.js, dashboard/styles.css, dashboard/index.html, tests/test_ux_ia_m0.py and existing domain analytics/period comparisons. Read Vercel Web Interface Guidelines, Anthropic frontend-design approach, official Agent Skills spec and Playwright accessibility-testing guidance.

This report is a **source-code audit only**. It does not establish that every component currently looks broken in a browser or that a real person has trouble using it. It identifies maintainability, consistency and usability *risks* warranting synthetic browser review.

## Findings (evidence → effect → priority)

### P0: UI architecture grows by addition, not composition

- dashboard/app.js is ~95 KB / ~1,811 lines with ~50 top-level functions, implementing all five views and multiple chart renderers.
- dashboard/styles.css is ~38 KB / ~530 lines, with 16 @media groups and multiple local sleep/cardio component families. This is maintainable today but increasingly expensive for agents to edit without unintended side effects.
- A single render() path reconstructs DOM for interaction states; inspect keyboard focus/scroll retention after a chart toggle. Avoid assuming that reconstructing DOM preserves focus automatically.
- **Action:** extract chart and control modules in small increments, keep API contracts unchanged, centralize token/interaction semantics and test all state transitions with synthetic browser fixtures. Do not jump to React merely because a file is long.

### P0: design quality is not tested in real rendered states

- Current tests check Python numerics, endpoint contracts, JS syntax and static strings, but no committed browser screenshot/diff or automated keyboard/a11y journey.
- GitHub Actions runs Python unittest and node --check only; these cannot establish responsive layout, chart legibility or focus flow.
- **Action:** add synthetic-only Playwright/axe quality harness after review of new dependencies; test 320/375/768/1280 widths, no horizontal overflow, and chart interactions; require manual screenshot approval. Never show real Oura records in CI or external tools.

### P1: visual hierarchy becomes flat

- Sidebar + topbar + large page heading and repeated card/panel sections all compete for attention.
- Sonno contains a generic period-comparison view, stage chart with 3 modes, weekly overview and per-night detail; although stage view is now moved up, users still must understand two different comparison interactions.
- Recupero similarly mixes baseline, timeseries, cross-domain correlations, and detailed intranight charts.
- **Action:** one dominant chart and one summary per screen; context and methods below or on demand. Avoid replacing important evidence with decorative status badges.

### P1: color and type have consistency/contrast risks

- Main root palette defines a small set of tokens (bg/surfaces/text/mint/blue), but phase chart colors and colors for comparison lines are mostly defined per selector.
- Current --dim = #657984 on --surface = #141e29 has **about 3.70:1 contrast**, below the WCAG 2.2 AA 4.5:1 target for normal-sized text. --dim appears in metadata, making it a likely accessibility priority. This is computed from declared CSS colors, not a browser-tested pixel result.
- The current UI frequently sets informational copy to 9–11px. Not automatically a standards violation, but likely tiring in dense trend inspection.
- Color differences among chart phases are useful, but A/B periods must also be distinguished by solid/dashed strokes, written labels and accessible table.
- **Action:** introduce semantic text/chart tokens, audit contrast across all states (not just background surfaces), raise useful labels to 12px+ and mobile inputs to 16px+.

### P1: sparse/missing data and freshness need a single language

- Data quality gates are relatively strong at the backend; multiple chart implementations each have their own null rendering and helper messages.
- Dates anchor to waking day, while comparisons sometimes anchor to latest qualifying night, not today.
- **Action:** shared CoverageLabel, MissingSeriesState, StaleDateLabel and consistent contextual n/N near deltas. A period without enough nights should still show available points but never invent an aggregate.

### P1: chart and interaction semantics are duplicative

- Sonno has both a generic comparison and specific light/deep/REM overlays, which can look like two equivalent ways to answer the same question despite different metrics/granularity.
- Custom SVG renderers in a large file repeat axis math, legends, tooltips and cursor logic. Consistency may drift after small isolated edits.
- **Action:** shared chart primitives and a domain-specific wrapper; preserve distinction between raw nights, rolling seven days and weekly aggregate. Avoid a single generic chart component with dozens of flags.

### P2: brand expression is under-defined

- Existing visual theme is dark, quiet and privacy-oriented, but current design also uses generic card grids, all-caps eyebrows and many similar rounded surfaces.
- **Action:** use product-specific distinction ("observe, compare, understand") rather than a "premium SaaS" decoration style. Reference the actual sleep and cardiovascular signals as the visual language.

## Keep — do not destroy working strengths

- Desktop/sidebar and mobile/bottom 5-domain navigation; both have clear programmatic tab IDs.
- Local Python deterministic calculations, field-level sample coverage, long_sleep selection and separation of phase/physiological units.
- SVG charts, browser-native HTML controls and plain CSS/JS (little network/dependency risk).
- Explicit read-only privacy design, no direct HTML injection, keyboard sliders and table equivalents already used in stage/cardio visualizations.
- Existing synthetic numerical test coverage and 7/30/90 contract verification on Mac.

## Strong recommendation

Do not first tweak twenty colors. Follow the UX redesign roadmap:
1. codify user job, hierarchy and skill checks;
2. introduce synthetic browser visual proof;
3. redesign Sonno as the reference page with large stage chart and accurate A/B compare;
4. migrate Recupero and Attivita using shared components;
5. verify visual/a11y and only then deploy to the private Mac.
